ArmorCode for Claude

Getting started with the armorcode-api skill and plugin

Version 1.1.0Claude Code · Claude Desktop · claude.ai

Ask Claude to report on, organize and change your ArmorCode tenant in plain language. Claude shows you every change as a dry run first, and nothing changes until you approve it.

1

Ask

"How many open criticals are external-facing under Payments?" Claude reads your tenant and answers with the numbers and the query it used.

2

Review a plan

For any change, Claude builds a dry run: tenant, risk level, exact diff, warnings. Nothing has changed yet.

3

Approve and verify

Only after you approve does it apply. It backs up what it touches, re-checks the result, and logs it.

Before you start

  • The Claude Desktop app (Code tab or Cowork) or Claude Code in a terminal or IDE. These run the plugin's approval prompt. Plain chat works with limits (see Install).
  • Python 3.8 or later on the machine where Claude runs commands. macOS and most Linux systems already have it. On Windows, install it from python.org (tick Add python.exe to PATH) or with winget install Python.Python.3.12.
  • HTTPS access from that machine to your ArmorCode host: app.armorcode.com, eu.armorcode.com, or your private instance.
  • An ArmorCode user whose role can create API keys (the Create Tools permission).
  • The plugin, from github.com/armor-code/armorcode-claude (see Install).
2

Install

The plugin is published at github.com/armor-code/armorcode-claude. It contains the skill and an approval hook: where the hook runs, Claude asks you before any change is sent to ArmorCode, even if Claude decided it should go ahead.

Claude Desktop app: Code tab (and Claude Code in a terminal or IDE)

# In a Claude Code session (Desktop Code tab, terminal or IDE)
/plugin marketplace add armor-code/armorcode-claude
/plugin install armorcode@armorcode
#    (in the Desktop Code tab you can also use + › Add plugins)

# or from a terminal
claude plugin marketplace add armor-code/armorcode-claude
claude plugin install armorcode@armorcode

Start a new session afterwards. Updates come from GitHub (see Updating).

Claude Desktop app: Cowork and chat

  1. Download armorcode-plugin-1.1.0.zip from the repository's Releases page.
  2. Open Customize › Plugins › Add › Upload plugin and choose the zip as is (don't unzip it).

Offline or without GitHub access

# unzip the release zip somewhere it can stay, then
claude plugin marketplace add ~/armorcode-plugin
claude plugin install armorcode@armorcode

For everyone in your organization

A Claude organization admin can add it once under Organization settings › Plugins & skills › Add › Upload plugin, and choose whether members can install it or get it by default.

Where the approval prompt runs. The hook runs in the Desktop Code tab, Cowork, and Claude Code in a terminal or IDE. It doesn't run in plain chat, where the plan-and-approve step and the CLI's own refusal to send unapproved changes are the safeguards. In chat on claude.ai, live calls also need your admin to allow network access to your ArmorCode host. Never paste an API key into a chat.
3

Create and store your API key

  1. In ArmorCode, go to Manage › Integrations › ArmorCode API › Create New Key.
  2. Choose key type API. Start with a read-only role, scope the key to the hierarchy or groups you need, and set an expiry.
  3. Copy the key once, straight into one of these. Never paste it into Claude.

macOS Keychain (recommended on a Mac)

security add-generic-password \
  -s armorcode-prod -a "$USER" -w
# prompts for the key; nothing lands in shell history

Environment variable (macOS, Linux)

# add to ~/.zshenv (macOS) or your shell profile
export ARMORCODE_TOKEN="…"
# then open a new terminal

Windows

Start menu › Edit environment variables for your account › User variables › New: name ARMORCODE_TOKEN, value: the key. Then quit and reopen Claude so it picks the variable up.

Claude reads the key only by the name of the variable or Keychain item; it never sees or prints the value. If a key is ever pasted into a chat, revoke it under Manage › Integrations and create a new one.

4

First conversation

Start a new Claude Code session and say:

"Set up the ArmorCode skill for our tenant. The API key is in the Keychain item armorcode-prod."
(or: "…in the environment variable ARMORCODE_TOKEN")

Claude creates a read-only profile, checks connectivity, and tells you the tenant, organizations and mode. For example:

Connected to https://app.armorcode.com as profile 'prod' (read-only · PRODUCTION)
Organizations (business units): Acme [1234], Archive [1235]
Groups visible to this key, all organizations: 412
This profile is read-only: plans can be built and reviewed, but `apply` is refused.

Read-only is the default. You can explore, report and plan as much as you like; nothing can be changed until you deliberately add a read-write profile with its own key:

"Add a read-write profile called prod-rw using the Keychain item armorcode-prod-rw, labelled 'PRODUCTION (changes)'."

6

How changes work

Every change follows the same four steps. Claude can't skip them: the bundled CLI refuses to send any change outside an approved plan, and a plan that was edited after you reviewed it won't run.

1

Read

Claude reads the current state and counts what your request would touch. If the request doesn't match reality (for example the rule matches nothing, or far more than expected), it stops and asks.

2

Plan (dry run)

It builds a plan and shows you the tenant, risk level, exact diff and warnings, then asks a direct question such as "Apply this to PRODUCTION?"

3

Approve

Only your explicit yes moves it forward. In Claude Code the plugin also shows its own approval prompt with the plan's steps. That's expected.

4

Apply and verify

It backs up each object, applies the change, waits for ArmorCode's background jobs, re-reads the result and reports what was verified, including any failures.

What a plan looks like

DRY RUN: nothing has been changed.

Plan      p-20261023-173030-49b7
Tenant    https://app.armorcode.com  [profile prod-rw · PRODUCTION (changes) · read-write]
Change    Update group 'checkout-api' (123456)
Risk      MEDIUM: full-object update done as read-merge-write at apply time
Steps     1
    1. Update group 'checkout-api' (123456)
         tier  '2' -> '1'
         tags  + business-impact:critical
         tags  - business-impact:high
Backups   each object is re-read and saved to ~/.armorcode/backups just before it is changed
Apply     ac.py apply p-20261023-173030-49b7 --confirm f41f57
Risk levelWhat it means for you
MEDIUMCreates or updates configuration such as a group, subgroup or saved view.
HIGHBulk finding changes, moves, uploads (which replace a tool's results), access changes, runbooks, and anything not on the low-risk list. Read it carefully.
CRITICALPermanent deletes and data purges. These need an extra, explicit flag, and Claude asks you specifically about the permanent part.
Built-in limits. Bulk finding changes are capped at 1,000 findings unless you explicitly ask for more. Claude refuses filters the API would silently ignore, and refuses settings that would quietly apply to future findings (standing rules, runbook back-fills) unless you ask for them by name.
7

Undo, backups and audit

If you need to…Ask Claude, or know that…
Undo a group or subgroup change"Restore group X from the backup taken before the last change." Backups live in ~/.armorcode/backups.
Undo a bulk finding change"Revert plan p-…". Prior status and severity are stored in every findings plan; only findings still holding the new value are reverted.
Undo a repository mappingThe plan file records each repo's previous mapping.
See what was changed"Show the ArmorCode audit log for this machine." Every applied step is logged in ~/.armorcode/audit.jsonl, and ArmorCode's own audit log records it under your user.
Undo a permanent delete, purge or runbook actionNot possible. Claude says so before asking you to approve one.
8

Using it is your call

The guardrails reduce the risk of mistakes; they don't eliminate it. Claude can misread a request, and APIs change. You decide whether to use the skill, which tenants and keys to use it with, and whether to approve each change. Changes made through it are made with your API key and count as your changes.

Start read-only

Reporting, exports, AQL checks and planning never change anything. Get comfortable there first.

Try changes somewhere safe first

Use a non-production tenant or organization before using a change-capable key elsewhere.

Read every plan

Check the tenant, counts and diff, and pilot large changes on a small slice first.

Keep keys narrow

Scope keys to a hierarchy or specific groups, set an expiry, and use one key per purpose.

9

Data handling

  • The bundled CLI runs on your machine and calls your ArmorCode host directly. The API key is never sent anywhere else and never follows a redirect.
  • API responses that Claude reads enter its context, and are handled under your organization's agreement and data settings with Anthropic. Scoped keys and file exports (--out) limit what Claude sees.
  • Local state lives in ~/.armorcode/ with owner-only permissions: profiles (no keys), plans, backups and the audit log. You can delete it at any time.
  • Claude is instructed to treat finding text, tags and comments as untrusted data, never as instructions.

Troubleshooting

You seeWhat to do
Environment variable … is not setAdd the export to ~/.zshenv (macOS) or your shell profile, open a new terminal, then restart Claude Code.
HTTP 401The key is wrong, expired, revoked, or for another tenant. Create a new one and check the host.
HTTP 403The key's role or scope doesn't allow that call, or it isn't an API-type key.
REFUSED: …A guardrail stopped something on purpose: a read-only profile, a filter typo, a count over the cap, a plan edited after review. The message says what to do.
Counts differ from the UIAsk Claude to reconcile them. Usual causes are status definitions, environment filters, organization scope, or a minute of indexing delay after big changes.
The skill doesn't appearDesktop app: check Customize › Plugins. Claude Code: run /plugin (or claude plugin list); it should show armorcode@armorcode enabled. Start a new session after installing.
Network or proxy errorsThe machine must reach your ArmorCode host over HTTPS. Behind a proxy, set HTTPS_PROXY.
11

Updating and removing

Desktop app (Cowork and chat): download the new zip from the Releases page and upload it under Customize › Plugins, replacing the old version. Remove it from the same screen.

# Claude Code / Desktop Code tab, update from GitHub
claude plugin marketplace update armorcode
claude plugin update armorcode@armorcode

# remove
claude plugin uninstall armorcode@armorcode
claude plugin marketplace remove armorcode
# optional: delete local profiles, plans, backups and the audit log
rm -r ~/.armorcode

Questions or unexpected behavior: open an issue at github.com/armor-code/armorcode-claude or contact your ArmorCode team, with what you asked, the plan id and the time. Never include an API key or tenant data.
